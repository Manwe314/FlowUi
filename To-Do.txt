the paradigm re design: COMPLETED
	- a lot of static work is done every frame. work beyond Layout. it should be simpler to aquire resources once and reuse across frames
	- elements might want to manage states. some long-lived variable management system would be nice, beyond a user-maintained struct.
	- closed elements that rely on `.draw()` while using other elements as children are forced to forward settable defaults, causing init functions to call exploding amounts of setters and getters.
	- a more preconfigured, easily tweakable reusable form of element should exist that does not also destroy the immediate mode paradigm.
	- reusability comes at a function-calling cost to not give up immediate mode. this should not be a tradeoff. both performance and unclogged files should be given without a sacrifice to immediate mode thinking.
