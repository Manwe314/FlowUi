  1. Suggested Data to Display at Targeted Points

The Inspector panel should dynamically adapt depending on what the user has selected. There are four natural targeted inspection states:

Targeted State Trigger Primary Purpose

  1. Selected Timing Zone Clicked a slice/cluster in a card/lane Root-cause diagnosis of a specific function
  2. Selected Frame Clicked a frame bar or stepped < / > Frame budget audit & phase breakdown
  3. Selected Scope / Zone Selected a zone/thread in left Selector Aggregate performance profile across history
  4. Global Overview (Idle) No item specifically selected Framerate health, jitter & profiler status
    ──────

    Targeted Point 1: Selected Timing Zone (Detailed Block Inspection)

When a user clicks a block slice in a timeline card or macro strip:

  1. Identity & Source:
    • Zone label (e.g. flowui.layout.scroll_update, flowui.element.invoke, flowui.gpu.ui_pass).
    • Category tag with semantic badge (Layout, Element, GPU, etc.) and Role (Work vs Wait / Gap).
    • Source file and line: UiManager.cpp:446 (with link/copy support).
  2. Execution Breakdown:
    • Total (Inclusive): e.g. 2.41 ms (and % of total frame time, e.g. 14.5%).
    • Self (Exclusive): e.g. 0.38 ms (15.8% of zone).
    • Children: e.g. 2.03 ms (84.2% of zone).
    • Visual horizontal split meter ([ Self |=========== Children ===========]).
  3. Entity Context (if Element / Window):
    • Element definition name (e.g. flowui.dev_interface.selector).
    • Element Instance ID (0x...).
    • Shortcut button: "Inspect Element in DOM" (navigates to the Inspect tab with this element selected).
  4. Historical & Statistical Context (from TimingRollingStatistics):
    • Rolling Mean: 1.85 ms · Min: 0.92 ms · Max: 4.10 ms.
    • Latency Percentiles: P50: 1.72 ms · P90: 2.30 ms · P99: 3.85 ms.
    • Delta vs P50: +0.69 ms (+40% spike) highlighted in amber if anomalous.
  5. Hardware & Pipeline Specifics:
    • CPU: Thread name (Main Thread (flowui.platform)), recursion depth.
    • GPU: Pipeline stages (TOP_OF_PIPE -> COLOR_ATTACHMENT_OUTPUT), Queue Family, CPU timestamp alignment deviation (±12 µs).
    • Flags: Warnings for DetailTruncated, ClockAnomaly, or Uncalibrated.

──────

Targeted Point 2: Selected Frame / App Tick

When a user clicks a frame column or uses transport controls (<, >, Spike):

  1. Frame Summary & Budget:
    • Frame number and App Tick ID (e.g. Frame #1,842 · Tick 2,109).
    • Frame duration vs 60 FPS / 120 FPS target budget (e.g. 18.24 ms -> Dropped frame / 54.8 FPS).
    • Budget gauge bar showing fill level (green under 16.6ms, red when overflowing).
  2. Phase Breakdown (Waterfall):
    • Direct comparison of major built-in phases:
    • flowui.frame.begin (Input, cursor, interaction snapshots)
    • flowui.frame.user_build (Element build passes)
    • flowui.frame.end (Clay layout calculations)
    • flowui.frame.draw (Draw command recording)
    • flowui.frame.prepared_gap (CPU/GPU synchronization & fence wait)
    • flowui.gpu.ui_pass / viewport_pass (Vulkan execution)
  3. Top Frame Culprits:
    • Top 3 longest zones by exclusive self-time.
    • Heaviest element definitions (from ElementDefinitionTimingAggregate /include/devSystems/devMonitoringAndReporting/timing/DevTimingTypes.
    hpp#L184): count, total ns, max single build ns.

──────

Targeted Point 3: Selected Scope / Zone from Left Selector

When a specific zone (or thread/window) is highlighted in the left Selector:

  1. Aggregate Distribution:
    • Total occurrences across retained history (e.g. 4,096 samples).
    • Invocation frequency: e.g. 1.0 / frame (regular) vs 42.5 / frame (hot loop).
    • Percentile distribution card: P50, P90, P95, P99.
  2. Spike Frequency & Jitter:
    • Standard deviation or spike count exceeding 1ms / 5ms.
    • Maximum observed outlier in history.

──────

Targeted Point 4: Global Overview (Idle / Nothing Targeted)

When no specific slice or frame is clicked:

  1. Realtime System Vital Signs:
    • Current FPS, Average Frame Time, P99 Frame Time over the last 120 ticks.
    • Primary bottleneck indicator: CPU Bound vs GPU Bound vs Wait/VSync Bound.
  2. DevMonitoring Engine Health (from TimingReportingStatus /include/devSystems/devMonitoringAndReporting/reporting/DevTimingReporting.hpp#L66 &
    TimingQualitySnapshot /include/devSystems/devMonitoringAndReporting/timing/DevTimingTypes.hpp#L201):
    • Retained history capacity: e.g. 4,096 / 4,096 ticks (100% full).
    • Profiler overhead: e.g. ~14 µs / frame (safe for production debugging).
    • Quality warnings (if any): Dropped records: 0, Misnested zones: 0, Clock anomalies: 0.

──────
