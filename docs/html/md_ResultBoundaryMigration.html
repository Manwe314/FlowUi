Implemented result boundaries

The direct authoring paths recommended in the boundary reassessment now return their values directly and propagate operational failures to the enclosing frame boundary. Useful resource, theme, configuration, registration and lifecycle results remain checked. Element callbacks retain their existing void or direct declaration return types.

Direct authoring operations

Surface Current return and failure behavior
UiManager::toClayString, toClaySID, toClayEID, imageData, inputContentElement Direct payload; operational failures throw and preserve frame-failure containment
Context clayID() with no name Direct Clay_ElementId; bridge failures propagate
UiManager::resolveFont Direct FontId, noexcept for attached-manager lookup; unavailable font resolves to zero
InputFieldManager::requestField Direct FieldQueryResult
replaceText, removeField, insertTextAtPrimaryCaret, enqueueCommand, submitTextSpan Direct bool; false remains a normal outcome
requestCaret, clear void; operational failures throw
getSelectedText Direct borrowed std::string_view with its existing invalidation rules
applyEdits Direct EditResult; normal rejection does not become an exception
PopupManager::dismiss, consumeDismissed void and direct bool, respectively

Direct operations do not acquire a new local-recovery promise. A latched frame error keeps the frame failed even if application code catches an exception. App::runFrame() owns cancellation and returns the selected typed error through Status. A latched frame error takes precedence over a later unlatched callback exception, including a later allocation or foreign exception; managed-window callback containment follows the same rule. Each manager retains its first error; UiManager::frameStatus() selects UI, then input-field, then popup failure state, rather than the earliest error across all managers. Cancellation does not reverse all pre-existing element state, applied edits, persistent manager changes or external application effects.

Named clayID(name), childID, part and theme lookups retain Results. PopupManager::request() retains its mixed checked contract: a direct duplicate rejection can be handled locally, while caught operational failure latches the frame. The conditional validation-only accessor recommendations are not a blanket removal of checked owner/registry access. ElementManager::prepare() retains its hybrid Status/exception contract and explicit retry of cached resource construction. Icon-disabled enumeration keeps the same checked return shape as the enabled build.

Public ValueOrThrow

Include Color.hpp, or a public umbrella that includes it. FlowUi::ValueOrThrow is declared beside Flow_Color:

const Clay_String label = ui.toClayString(text);
const Clay_ElementId root = context.clayID();
const auto& theme = FlowUi::ValueOrThrow(ui.theme<FlowUi::FSEL::FSELTheme>()).get();
FlowUi::ValueOrThrow(app.setClipboardText("Copied text"));

The helper applies only to retained Result<T>/Status values. It throws FlowUiException containing the unchanged FlowUiError; it does not report, retry, select a fallback or clear frame failure.

Argument Return/ownership
Result<T>& Borrowed T& valid while the result/payload remains valid
const Result<T>& Borrowed const T&
Result<T>&& Owned T moved from the successful payload; supports move-only values
const Result<T>&& Owned copied T; requires a copyable payload
Status void; successful completion returns normally

Moving a reference_wrapper, pointer or view still does not acquire the referred object's ownership. Payload copy/move exceptions can propagate separately. All forms intentionally permit throwing. The helper preserves the original error with either the standard expected backend or FlowUi's compatibility backend.
