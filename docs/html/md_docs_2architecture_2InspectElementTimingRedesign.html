Inspect Workbench: Element Instance & Definition Timing Redesign

1. Executive Summary & Design Rationale

In DevInspectWorkbench.cpp, the FRAME & CONSTRUCT TIMING section inside the Inspect Workbench panel previously devoted 4 metric slots to whole-application frame statistics (Current, EMA, Min / max, Jitter).

The Problem

  • The Inspect Workbench is element-instance and definition-centric. Developers inspect a selected node to analyze that specific element's construction overhead, subtree cost, and definition efficiency.
  • Displaying full-frame diagnostics (min/max frame range, overall frame jitter) in the Inspect Workbench clutters the interface with application-wide data that properly belongs on the dedicated Performance Workbench Tab (DevPerformanceWorkbench.cpp).
  • Furthermore, developers lack immediate visibility into the compiled CPU timing depth (FLOWUI_DEV_TIMING_LEVEL) and the currently active runtime timing level, making it ambiguous whether subtree or deep instance measurements are currently compiled and captured.

The Solution

Redesign the Inspect Workbench timing section to be 100% Element Instance & Definition Centric:

  1. Timing Level Status Indicator: Display the compiled maximum timing level (e.g. Level 2) and currently active runtime level (Level 2 (Balanced)) directly in the section header.
  2. Compact Global Frame Context: Reduce full-frame telemetry to a single lightweight sub-header tag (Frame EMA 16.50 ms ± 1.45 ms).
  3. Hero Element Instance Telemetry: Prominently feature the selected element's Self / Local Instance Time and Subtree Construct Time with large typography and percentile selector controls (P50 to MAX).
  4. Definition Efficiency Grid: Dedicated 3-column percentage grid for shared element definition metrics (Definition Avg, Peak Time, Invocation Count & Live Instances).

3. Detailed Component & Metric Specifications

3.1 Timing Level Indicator & Status Header

  • Compiled Level (FLOWUI_DEV_TIMING_LEVEL):
    • 0: Frame Only (basic frame total timing).
    • 1: Summary (element invoke boundaries & top-level timing).
    • 2: Balanced (full element instance & subtree timings).
    • 3: Deep (granular internal pass & layout phase timings).
  • Active Level (DevTimingConfig::minimumCpuLevel):
    • Live runtime active level. Displayed in header as [LEVEL <Active>/<Compiled> <Name>] (e.g. [LEVEL 2/2 BALANCED]).

3.2 Compact Frame Context Line

  • Replaces the old 4-item frame row with a single compact sub-header text string: Frame: 16.67 ms (EMA 16.50 ms ± 1.45 ms)
  • Keeps essential frame pacing context visible without consuming grid real estate.

3.3 Hero Instance Telemetry Block

Two prominent 50% (CLAY_SIZING_PERCENT(0.5f)) equal-width cells with horizontal clipping:

  1. Instance Self Time: Duration spent strictly executing this element's logic (kElementInvoke).
  2. Subtree Construct Time: Cumulative duration spent constructing this element and its entire descendant tree (kElementConstructedSubtree).

3.4 Definition Telemetry Grid

Three 33.3% (CLAY_SIZING_PERCENT(1.0f / 3.0f)) equal-width cells with horizontal clipping:

  1. Definition Average: Average construction duration per call across all instances of this definition.
  2. Definition Peak: Maximum (worst-case) single invocation time recorded in the sample window.
  3. Invocations & Active: Invocation call count in window and active instance count.

  3. Refactor kOverviewPerformance block layout in DevOverviewAndPerformance::buildElement:
    • Render section title + [LEVEL 2/2 BALANCED] badge in header.
    • Render compact frameSummary text line.
    • Render percentile selector (P50 .. MAX).
    • Render Hero Instance row (50% / 50% percentage split).
    • Render Definition Grid row (33.3% / 33.3% / 33.3% percentage split).
