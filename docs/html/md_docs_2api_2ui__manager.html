UI Manager API

UiManager.hpp is the frame-scoped application authoring surface. App owns its lifecycle. Obtain it from the checked App::ui() accessor; once acquired, ui.actions() and ui.elements() return direct borrowed references. The App::actions() and App::elements() accessors themselves return checked wrappers.

auto uiResult = app.ui();
if (!uiResult) {
throw FlowUi::FlowUiException(uiResult.error());
}
FlowUi::UiManager& ui = uiResult->get();
auto status = ui.setClipboardText("Copied text");
if (!status) {
throw FlowUi::FlowUiException(status.error());
}

Frame storage and bridge helpers return direct values and throw on operational failure. resolveFont() returns a direct FontId without throwing for an attached manager. Theme lookups, clipboard operations and frame status retain their declared checked results. Builder creation, drawing, manager borrowing and action invocation remain direct throwing APIs. In custom composition, retain the first failure with recordFrameError() and cancel a failed frame. Exceptions from application callbacks are allowed to reach the enclosing application frame boundary; output from that failed frame must not be submitted. See result handling.

Clay_String, image payload pointers and frame bridge data borrow current-frame storage. Input/interaction references borrow this manager; do not keep them as frozen snapshots across later frames. Font aliases are FontId = uint16_t and FontFamilyId = uint32_t; CursorType names platform cursor shapes. UI types define FrameInput, InteractionSnapshot and TextureRef.

The createElement() examples use the complete Counter definition in the element API. Development builds append an optional std::source_location argument to every createElement() overload. FLOW_UI_DEV_MODE and FLOW_UI_AGENTIC_WORKFLOW also expose observation/configuration helpers for tooling; those conditional implementation-facing services are outside the application reference below.

Interaction snapshots and texture values

InteractionSnapshot contains contiguous hoveredElementIds, pressedElementIds, heldElementIds and releasedElementIds vectors. These store Clay numeric identities for one completed frame. The primary pointer can appear in several lists when the recorded transitions permit it. All four observers below accept Clay, local Flow, global Flow and semantic-part Flow IDs directly; strong Flow identities are folded using the bridge identity convention. A false observation is ordinary absence, with no Result wrapper.
