◆ beginFrame() [1/2]

Status FlowUi::App::beginFrame ( )
nodiscard

Set whether the window backend should request shutdown.

The value argument is passed to the GLFW built-in window backend. Zero clears the window close flag; a non-zero value sets it.

Example:

while (!application.shouldClose()) {
if (error()) {
application.setShouldClose(1);
}
}
/
void setShouldClose(int value);
void setShouldClose(WindowId id, int value);
Precondition
The FlowUi::App instance is initialized and its window/UI systems are valid.
Postcondition
The current frame is active and input/UI state is ready for frame logic/building.
Note
Do not also call pollEvents() in the same loop iteration unless a second global event-pump pass is intentional.
See also
Frame Lifecycle
Quick Start

◆ beginFrame() [2/2]

Status FlowUi::App::beginFrame ( WindowId id)
nodiscard

Begin one explicit window frame without polling global events.

Use this overload after one pollEvents() call when driving multiple windows; id must identify a registered window. A window's beginFrame(id), endFrame(id), and drawFrame(id) triplet must finish before another window frame is begun.

Precondition
pollEvents() was called at the cadence required by the application.
Postcondition
The selected window's UI manager is ready for frame construction.

◆ drawFrame() [1/2]

Status FlowUi::App::drawFrame ( )
nodiscard

Submit the current frame for rendering and presentation.

Takes the render commands output by endFrame(), builds GPU draw runs, renders them, and passes the output to the swapchain for presentation.

Example:

Precondition
FlowUi::App::endFrame() was called successfully.
Postcondition
This frame is rendered and presented.
Note
This function should be called exactly once per frame.
After presenting the main window, this overload synchronously calls dispatchManagedWindows(). The WindowId overload never dispatches managed windows implicitly.

◆ pollEvents()

Status FlowUi::App::pollEvents ( )
nodiscard

Poll global platform events and advance app-shared maintenance.

Multi-window applications should call this once per outer application-loop iteration before beginning explicit window frames. The function is global, not associated with one WindowId, and cannot run while a window frame triplet is active.

Single-main-window applications normally do not call this directly because the no-argument beginFrame() overload performs the same polling first.

Exceptions
std::logic_errorif a window frame triplet is active or the call is made from outside the app's platform thread.
