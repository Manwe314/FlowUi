Frame & Construct Timing Width Stability Design

1. Executive Summary & Problem Overview

In DevInspectWorkbench.hpp, the DevOverviewAndPerformance element renders live execution telemetry for selected Flow nodes within the DevInspect workbench. A core section of this panel is the Frame & Construct Timing block (kOverviewPerformance), which displays real-time frame rates, EMA timing, min/max ranges, jitter variance, percentile timings, peak times, and call counts.

The Issue

Because timing statistics are measured live on every frame, string representations (e.g., currentFrame, smoothFrame, frameRange, jitter, instanceTiming, subtreeTiming, definitionTiming, definitionPeak, and invocationCount) update continuously.

Under Clay UI's flex layout engine, CLAY_TEXT elements measure unclipped string widths based on font glyph metrics. In the current implementation of drawOverviewMetric in DevInspectWorkbench.cpp, metric rows use CLAY_SIZING_GROW(0) without an explicit minimum width override (.min = 0). Consequently:

  1. Clay calculates the intrinsic minimum width (min_width) of each metric column from the sum of its label and value text measurements.
  2. Character length variations (e.g., 1.23 ms / 813.0 FPS vs 16.67 ms / 60.0 FPS vs 120.45 ms / 8.3 FPS) and glyph width changes alter min_width on every single frame.
  3. In multi-column rows like frame-row and timing-row, fluctuating min_width values propagate up to overviewPanel(), then to DevOverviewAndPerformance, and finally to DevWorkbenchCard in kTopRow (DevInspectWorkbench.cpp).
  4. This causes the outer card (DevWorkbenchCard) and its sibling DevPreview card to constantly jitter horizontally, especially when panel width is constrained.

This design document outlines a structural UI layout refactor to completely isolate text value changes from layout sizing, ensuring 100% stability of the outer card width under all screen dimensions.

2. Root Cause & Clay Layout Mechanics

2.1 Current Layout Hierarchy & Propagation Chain

2.2 Mechanism of Jitter

  • Flex Intrinsic Size Propagation: When a child container in Clay uses CLAY_SIZING_GROW(0), Clay sets .type = CLAY__SIZING_TYPE_GROW with default .size.minMax = {0, 0}. Clay's layout pass queries child CLAY_TEXT nodes to compute the minimum required width (min_width).
  • Frame-by-Frame Reflow: When string content changes frame-by-frame, min_width of frame-row and timing-row changes continuously.
  • Outer Card Flex Shift: kTopRow splits horizontal space between Preview and OverviewAndPerformance. As OverviewAndPerformance requests a different minimum width every frame, the flex allocation shifts, producing horizontal jitter.
  • Narrow Width Constrained Behavior: When horizontal space is restricted, text nodes compete for available pixels, shifting truncation points back and forth every frame and compounding visual stutter.

3. Structural Architectural Solution

To eliminate width jitter without sacrificing live telemetry updates, we enforce a strict Zero-Min Flex Containment Architecture:

Key Pillars of the Design

Key Pillars of the Design

  1. Percentage-Based Initial Sizing Isolation (CLAY_SIZING_PERCENT): In Clay's pass 1 element measurement phase, layout elements with CLAY_SIZING_GROW compute initial unclipped content dimensions by summing child text measurements. If a child text string changes width frame-by-frame, the row's initial dimensions.width fluctuates and propagates up to the outer workbench card. By setting column children to CLAY_SIZING_PERCENT(0.25f) (or 0.2f, 1.0f / 3.0f, 0.5f), Clay explicitly forces child->dimensions.width = 0 during pass 1. This decouples row/panel/card dimensions entirely from string lengths, guaranteeing 100% rigid outer card width.
  2. Horizontal Text Clipping (clip = {.horizontal = true}): Each metric container isolates its inner content with .clip = {.horizontal = true}. In pass 2 space distribution, Clay allocates exact equal percentage slices of row width (e.g. 25% for 4 columns). When row width is constrained, dynamic text strings clip silently at the right edge of their allocated percentage slot instead of expanding parent container bounds.
  3. Decoupled Label & Value Layout: Each metric cell is rendered with .width = widthSizing (e.g., CLAY_SIZING_PERCENT(0.25f)). Inside each metric cell, dynamic value text is wrapped in a zero-min clipped flex box (CLAY_SIZING_GROW(0) with horizontal clipping).
  4. Compact Metric Formatting: Standardize timing telemetry string formatting in populateFrameStatistics (DevInspectWorkbench.cpp) and metric display helpers to ensure consistent character counts and clean decimal truncation.

4. Detailed Code Implementation Plan

4.1 Refactoring drawOverviewMetric in src/devSystems/devInterface/Inspect/Workbench/DevInspectWorkbench.cpp

Update drawOverviewMetric in DevInspectWorkbench.cpp to accept a configurable widthSizing parameter:

template <typename Context>
void drawOverviewMetric(
Context& context,
IndexedElementName id,
std::string_view label,
std::string_view value,
Clay_Color valueColor = interface_theme::kTextCanvas,
Clay_SizingAxis widthSizing = CLAY_SIZING_GROW(0)) {
Clay_ElementDeclaration row{};
row.layout.sizing = {
.width = widthSizing, .height = CLAY_SIZING_FIXED(14.0f)};
row.layout.layoutDirection = CLAY_LEFT_TO_RIGHT;
row.layout.childGap = 6;
row.layout.childAlignment = {
.x = CLAY_ALIGN_X_LEFT, .y = CLAY_ALIGN_Y_CENTER};
row.clip = {.horizontal = true, .vertical = true};
CLAY(context.clayID(id), row) {
CLAY_TEXT(context.uiManager.toClayString(label),
CLAY_TEXT_CONFIG(textConfig(interface_theme::kTextSecondary, 8)));
Clay_ElementDeclaration valueBox{};
valueBox.layout.sizing = {
.width = CLAY_SIZING_GROW(0), .height = CLAY_SIZING_GROW(0)};
valueBox.layout.childAlignment = {
.x = CLAY_ALIGN_X_LEFT, .y = CLAY_ALIGN_Y_CENTER};
valueBox.clip = {.horizontal = true, .vertical = true};
CLAY(context.clayID("val-box"), valueBox) {
CLAY_TEXT(context.uiManager.toClayString(value),
CLAY_TEXT_CONFIG(textConfig(valueColor, 9)));
}
}
}

5. Verification & Testing Protocol

  1. Compilation Verification:
    cmake -B build -DCMAKE_BUILD_TYPE=Debug -DCMAKE_EXPORT_COMPILE_COMMANDS=ON
    cmake --build build --target FlowUi -j
  2. Runtime Layout Stability Test:
    • Run the application with FLOW_UI_DEV_MODE enabled.
    • Select an element in the inspector to open DevInspectWorkbench.
    • Observe DevOverviewAndPerformance under active animation/frame updates. Verify that DevWorkbenchCard outer width and column widths remain 100% rigid with 0px jitter.
  3. Constrained Width Test:
    • Narrow the application window to minimum width.
    • Verify that dynamic timing values clip horizontally within their zero-min flex cells without expanding the outer card or overflowing sibling cards.
