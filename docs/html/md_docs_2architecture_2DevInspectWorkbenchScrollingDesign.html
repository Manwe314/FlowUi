DevInspectWorkbench Vertical Bounding & Scrolling Design

1. Executive Summary & Problem Overview

In DevInspectWorkbench.hpp and DevInspectWorkbench.cpp, the DevInspectWorkbench element organizes developer tools for an inspected Flow element into a 2x2 grid card workspace:

  • Top Row: DevPreview (Preview Canvas & Camera) and DevOverviewAndPerformance (Timing, Geometry & Memory).
  • Bottom Row: DevChangesAndDiagnostics (Active Overrides & Element Issues) and DevClaySubTree (Clay Layout Primitives Tree).

The Issue

When an inspected element emits a moderate-to-large Clay subtree (or when multiple nodes are expanded in the subtree hierarchy), the DevClaySubTree card expands vertically to fit the entire expanded subtree height rather than remaining bounded within its allotted workbench card area.

As a result:

  1. The kBottomRow container and the overall workbench expand downward by hundreds or thousands of pixels, pushing the bottom half of the workbench past the viewport boundary.
  2. The treeList container inside DevClaySubTree does not register an overflow condition because its height expands to match treeContent.dimensions.height.
  3. Vertical scrolling via mouse wheel or drag scrolling cannot function because Clay sees zero difference between scroll container dimensions and inner content dimensions.
  4. Other elements in the workbench (such as DevChangesAndDiagnostics and DevOverviewAndPerformance) either artificially truncate their contents or risk compounding the vertical overflow.

This design document outlines the root cause within Clay's two-pass layout engine and details the structural layout refactoring required to strictly bound the workbench elements to their allocated heights and restore vertical scrollability.

2. Root Cause Analysis & Clay Layout Mechanics

2.1 The Element Hierarchy

The containment chain from the developer workspace window down to the tree nodes is:

DevWorkbenchArea (in DevContentAreas.cpp)
└── DevInspectWorkbench (root, CLAY_TOP_TO_BOTTOM)
├── DevInspectWorkbenchHeader (FIXED: 40px)
├── DevInspectWorkbenchSubtitle (FIXED: 24px)
└── DevInspectWorkbenchContent (CLAY_TOP_TO_BOTTOM)
├── kTopRow (CLAY_LEFT_TO_RIGHT)
│ ├── DevWorkbenchCard (kPreview)
│ └── DevWorkbenchCard (kOverviewAndPerformance)
└── kBottomRow (CLAY_LEFT_TO_RIGHT)
├── DevWorkbenchCard (kChangesAndDiagnostics)
└── DevWorkbenchCard (kClaySubTree)
└── DevClaySubTree
├── summaryBar (FIXED: 32px)
└── treeList (Scroll Container: context.clayID("tree-list"))
└── treeContent (FIT: sum of all kDevNode items)

2.2 Why DevClaySubTree Expands Instead of Scrolling

Clay layout execution proceeds in two distinct phases:

Phase 1: Bottom-Up Depth-First Sizing (Clay__CalculateFinalLayout)

During this pass, Clay calculates intrinsic child heights and propagates them up through parent nodes:

// external/clay.h: lines 2692-2701
} else if (layoutConfig->layoutDirection == CLAY_TOP_TO_BOTTOM) {
float contentHeight = (float)(layoutConfig->padding.top + layoutConfig->padding.bottom);
for (int32_t j = 0; j < currentElement->children.length; ++j) {
Clay_LayoutElement *childElement = Clay_LayoutElementArray_Get(&context->layoutElements, currentElement->children.elements[j]);
contentHeight += childElement->dimensions.height;
}
contentHeight += (float)(CLAY__MAX(currentElement->children.length - 1, 0) * layoutConfig->childGap);
currentElement->dimensions.height = CLAY__MIN(CLAY__MAX(contentHeight, layoutConfig->sizing.height.size.minMax.min), layoutConfig->sizing.height.size.minMax.max);
}
  1. In DevClaySubTree, each node in treeContent adds ~36px. With 50 nodes, treeContent.dimensions.height reaches ~1800px.
  2. Because treeList has .height = CLAY_SIZING_GROW(0), its minMax.max is 0 (unbounded). treeList.dimensions.height becomes 1800px.
  3. DevClaySubTree container has .height = CLAY_SIZING_GROW(0). Its height becomes 32px + 1800px = 1832px.
  4. DevWorkbenchCard has .height = CLAY_SIZING_GROW(0). Its height becomes 1832px.
  5. In kBottomRow (CLAY_LEFT_TO_RIGHT), off-axis height takes the maximum of its children: kBottomRow.dimensions.height = 1832px.
  6. In DevInspectWorkbenchContent, content.dimensions.height sums kTopRow + kBottomRow (~2200px+).
  7. In DevInspectWorkbench, root.dimensions.height sums header + subtitle + content (~2300px+).

Phase 2: Top-Down Breadth-First Space Distribution (Clay__SizeContainersAlongAxis)

During this pass, Clay distributes available space from ancestors to children. However, Clay applies a critical bypass when ancestors have clipping enabled:

// external/clay.h: lines 2416-2420
if (sizeToDistribute < 0) {
// If the parent clips content in this axis direction, don't compress children, just leave them alone
if (((xAxis && parent->config.clip.horizontal) || (!xAxis && parent->config.clip.vertical))) {
continue;
}
...
// external/clay.h: lines 2511-2515
float maxSize = parentSize - parentPadding;
if (((xAxis && parent->config.clip.horizontal) || (!xAxis && parent->config.clip.vertical))) {
maxSize = CLAY__MAX(maxSize, innerContentSize);
}
  1. DevWorkbenchArea has clip = {.horizontal = true, .vertical = true}.
  2. When Clay processes DevWorkbenchArea, parent->config.clip.vertical is true and sizeToDistribute < 0. Clay explicitly skips compression of DevInspectWorkbench.
  3. Furthermore, because DevWorkbenchCard also sets card.clip = {.horizontal = true, .vertical = true}, Clay treats card as a scroll container parent and sets maxSize = CLAY__MAX(maxSize, innerContentSize). Any child using CLAY_SIZING_GROW(0) is expanded to innerContentSize!
  4. Consequently, treeList.dimensions.height remains 1800px, identical to treeContent.dimensions.height.
  5. Clay evaluates scrollability by checking whether scrollContainerDimensions.height < contentDimensions.height. Since both are 1800px, no overflow occurs, scroll offset remains zero, and wheel input does nothing.

2.3 How Other Panels Fixed This

In DevInspectInspector.cpp, the exact same architecture exists, with an explicit architectural comment:

Clay_ElementDeclaration root{};
// The column clips overflow, so GROW would expand to the content size.
// Bound the panel to the column so its inner scroll region can overflow.
root.layout.sizing = {
.width = CLAY_SIZING_PERCENT(1),
.height = CLAY_SIZING_PERCENT(1),
};

When CLAY_SIZING_PERCENT is used, Clay calculates dimensions via:

// external/clay.h: line 2405
*childSize = (parentSize - totalPaddingAndChildGaps) * childSizing.size.percent;

Percentage sizing is calculated unconditionally during the top-down pass based on the parent's actual bounding dimensions, bypassing the sizeToDistribute < 0 clipping escape and constraining the child to the parent bounds.

3. Implemented Architecture & Sizing Hierarchy

To guarantee that the workbench and all four cards remain bounded to the available viewport height while enabling smooth vertical scrolling, the following layout constraints were implemented:

3.1 Bounding the Workbench Root

In DevInspectWorkbench.cpp:

Clay_ElementDeclaration root{};
root.layout.sizing = {
.width = CLAY_SIZING_PERCENT(1.0f),
.height = CLAY_SIZING_PERCENT(1.0f),
};
root.layout.layoutDirection = CLAY_TOP_TO_BOTTOM;
  • Restricts DevInspectWorkbench to exactly 100% of the DevWorkbenchArea viewport.

3.2 Sizing the Content and Grid Rows

In DevInspectWorkbench.cpp:

Clay_ElementDeclaration row{};
row.layout.sizing = {
.width = CLAY_SIZING_GROW(0),
.height = CLAY_SIZING_PERCENT(0.5f),
};
row.layout.layoutDirection = CLAY_LEFT_TO_RIGHT;
row.layout.childGap = kWorkbenchGap;
  • kTopRow and kBottomRow use CLAY_SIZING_PERCENT(0.5f).
  • Clay allocates each row: (contentHeight - 2 * kWorkbenchPadding - kWorkbenchGap) * 0.5f.
  • The two rows together strictly consume 100% of the content height. Neither row can expand vertically.

3.3 Constraining the Workbench Cards

In DevInspectWorkbench.cpp:

void DevWorkbenchCard::buildElement(BuildContext& context) {
Clay_ElementDeclaration card{};
card.layout.sizing = {
.width = CLAY_SIZING_PERCENT(0.5f),
.height = CLAY_SIZING_PERCENT(1.0f),
};
card.backgroundColor = interface_theme::kDepth1Panel;
card.cornerRadius = CLAY_CORNER_RADIUS(5);
card.border = {
.color = interface_theme::kBorderPrimary,
.width = Clay_BorderWidth{1, 1, 1, 1, 0},
};
card.clip = {.horizontal = true, .vertical = true};
...
}
  • Width is CLAY_SIZING_PERCENT(0.5f), sharing horizontal space equally.
  • Height is CLAY_SIZING_PERCENT(1.0f), locking the card to 100% of the row's height.

3.4 Sizing and Scrolling within DevClaySubTree

In DevInspectWorkbench.cpp:

void DevClaySubTree::buildElement(BuildContext& context) {
Clay_ElementDeclaration container{};
container.layout.sizing = {
.width = CLAY_SIZING_PERCENT(1.0f),
.height = CLAY_SIZING_PERCENT(1.0f),
};
container.backgroundColor = interface_theme::kDepth0Keel;
container.layout.layoutDirection = CLAY_TOP_TO_BOTTOM;
CLAY(context.clayID(), container) {
...
// Summary Bar Header
Clay_ElementDeclaration summaryBar{};
summaryBar.layout.sizing = {
.width = CLAY_SIZING_GROW(0),
.height = CLAY_SIZING_FIXED(32.0f),
};
...
// Scrollable Tree List
Clay_ElementDeclaration treeList{};
treeList.layout.sizing = {
.width = CLAY_SIZING_GROW(0),
.height = CLAY_SIZING_GROW(0),
};
treeList.layout.layoutDirection = CLAY_TOP_TO_BOTTOM;
const Clay_ScrollContainerData scroll = Clay_GetScrollContainerData(context.clayID("tree-list"));
treeList.clip = {
.vertical = true,
.childOffset = scroll.found && scroll.scrollPosition
? *scroll.scrollPosition : Clay_Vector2{},
};
CLAY(context.clayID("tree-list"), treeList) {
Clay_ElementDeclaration treeContent{};
treeContent.layout.sizing = {
.width = CLAY_SIZING_GROW(0),
.height = CLAY_SIZING_FIT(0),
};
...
}
}
}
  1. container has CLAY_SIZING_PERCENT(1.0f), matching the card height.
  2. summaryBar takes a fixed 32px at the top.
  3. treeList receives cardHeight - 32px.
  4. treeContent measures the total height of all rendered nodes.
  5. When treeContent.height > treeList.height, treeList overflows. Clay assigns scroll boundaries, and mouse wheel/drag scrolling immediately functions.

4. Bounding and Scrolling across Other Workbench Elements

  1. DevOverviewAndPerformance:
    • Root sizing set to CLAY_SIZING_PERCENT(1.0f), CLAY_SIZING_PERCENT(1.0f).
    • kOverviewBody wired with Clay_GetScrollContainerData(context.clayID(kOverviewBody)) and childOffset = scroll.found && scroll.scrollPosition ? *scroll.scrollPosition : Clay_Vector2{}. Enables vertical scrolling for the 4 overview panels on constrained windows.
  2. DevChangesAndDiagnostics:
    • Root sizing set to CLAY_SIZING_PERCENT(1.0f), CLAY_SIZING_PERCENT(1.0f).
    • kChangesBody wired with Clay_GetScrollContainerData(context.clayID(kChangesBody)) and childOffset.
  3. DevPreview:
    • Root sizing set to CLAY_SIZING_PERCENT(1.0f), CLAY_SIZING_PERCENT(1.0f).
    • Preserves fixed 36px toolbar with canvas filling remaining bounded area.
