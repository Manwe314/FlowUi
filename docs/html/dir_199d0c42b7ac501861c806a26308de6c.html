Detailed Description

These Draft 2020-12 schemas describe the version 1 wire contracts. All 64-bit IDs, byte counts, sequence values, and nanoseconds are decimal strings. The C++ codecs additionally check the unsigned 64-bit range, half-open interval order, duplicate IDs/paths, manifest inventory references, exact hashes and root confinement. Native timing CSV and diagnostics artifacts retain their separately declared schemas.

The source dictionary is a JSON array and the scenario declaration is a bare typed object; their manifest inventory supplies schema/version identity. Other evidence records carry their own envelope. Nullable fields and local $defs references are validated by the same runtime validator. Schema generation rejects unsupported validation keywords and external references.

  • Capture envelope

  • Owned Flow/Clay tree: topology, exact frame identity, geometry and pointer-presence flags; runtime checks also enforce index bounds.
  • Typed themes: variants, reflected field constraints and authored/effective/preview distinctions.
  • Resource and element catalogue: typed resource keys, owned metadata and revision identities.
  • Source dictionary: bounded source locators retained under the capture inventory.
  • Scenario declaration and action/assertion records: declared workloads, phase progress and semantic action evidence.
  • Memory sources, events and weighted summary: producer identities, exact quantities and interval-weighting semantics.
  • Performance summary and timing contributors: continuous cadence segments, distributions and ranked exclusive scoped costs.
  • Comparison result and immutable comparison manifest: comparability, referenced captures and final-byte inventory.
  • Command request: common typed command envelope.
  • Verification request: sequential scenario or interaction workloads, exact revisions, bounded deadlines and checkpoint budgets; unknown fields and unsupported versions are rejected.
  • Verification report: execution status, independent assertion verdict and coverage, cleanup, resource availability and durable evidence selectors.
  • Interaction plan: finite source frames/spans or mechanical steps, coordinate/baseline/content policies, and optional deterministic compiler estimates.
  • Selected input receipt: complete effective input, optional native assessment, actual consumed frame and explicit text-redaction/replayability facts.
  • Interaction observation: genuine completed consumer facts, revisioned resolved geometry and optional application-owned target evidence.
  • Interaction result: independent delivery/observation/assertion coverage, cleanup/handoff, first divergence and optional exported-action receipt.
  • Interaction capabilities: advertised mechanics, observation domains, key mapping and input-clock semantics.
  • Store identity, run provenance, session state, instance endpoint and rebuildable index: lifecycle and discovery metadata.
